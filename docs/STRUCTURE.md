# Banglasketch folder guide

## Current structure

The website uses Next.js and the backend is now Django. The former Express backend has been removed from the working tree. Keep a backup or tagged commit of the old backend until the Django replacement has been verified in production.

```text
banglasketch/
├── frontend/                   Website and custom admin interface
│   ├── app/                    Pages and Next.js server routes
│   │   ├── admin/              Staff dashboard and content editing
│   │   ├── api/                Frontend server handlers and backend proxies
│   │   ├── portfolio/          Public project pages
│   │   ├── blog/               Public articles
│   │   └── portal/             Client-facing portal
│   ├── components/             Reusable UI components
│   ├── lib/                    API calls, authentication helpers, utilities
│   ├── types/                  Shared TypeScript data definitions
│   ├── styles/                 Shared styles
│   ├── public/                 Static assets
│   └── data/                   Local application data
│
├── django_backend/             New Python API — migration in progress
│   ├── banglasketch_api/        Django settings, root URLs, WSGI/ASGI
│   ├── apps/                   Features grouped by business purpose
│   │   ├── authentication/     Admin identity, tokens, passwords and 2FA
│   │   ├── projects/           Public portfolio projects and editing
│   │   ├── blog/               Articles and publication
│   │   ├── media_assets/       Videos and testimonials
│   │   ├── leads/              Contact submissions and newsletter
│   │   ├── clients/            Enquiries, client projects and proposals
│   │   └── core/               Shared settings and platform endpoints
│   ├── tests/                  Tests spanning multiple features
│   ├── manage.py               Django command entry point
│   └── requirements.txt        Python dependencies
│
├── docs/                       Architecture, migration and deployment guides
├── README.md                   Project introduction and setup

├── ecosystem.config.js         Current PM2 deployment configuration
├── nginx.conf.example          Nginx deployment template
└── cpanel.htaccess.example      cPanel deployment template
```

## Where to make changes

| Task | Location |
| --- | --- |
| Change a public page or admin screen | `frontend/app/` |
| Change a reusable button, form or card | `frontend/components/` |
| Change how Next.js calls the backend | `frontend/lib/api.ts` and `frontend/app/api/` |
| Fix an API endpoint | Matching folder in `django_backend/apps/` |
| Implement a Django feature | Matching folder in `django_backend/apps/` |
| Change Django configuration or API registration | `django_backend/banglasketch_api/` |
| Understand migration gaps | [DJANGO_MIGRATION_AUDIT.md](DJANGO_MIGRATION_AUDIT.md) |

Within each Django app, use `models.py` for database models, `serializers.py` for API validation and representation, `views.py` for HTTP handling, `urls.py` for routes, `admin.py` for Django admin registration, `migrations/` for schema history and `tests.py` for feature tests. Add `services.py` when business workflows need separation from HTTP handling; create additional folders only as the feature grows.

Portfolio `projects` are public showcases. `clients` manages actual client work, enquiries and proposals. These have different purposes and should stay separate.

## Generated folders and cleanup

| Folder/file | Purpose | Cleanup guidance |
| --- | --- | --- |
| `__pycache__/`, `*.pyc` | Python bytecode cache | Regenerated automatically; safe to remove |
| `frontend/.next/` | Next.js compiled output and cache | Remove after stopping Next.js; rebuild before production start |
| `*.tsbuildinfo` | TypeScript incremental cache | Regenerated by type checks/builds |
| `node_modules/` | Installed JavaScript dependencies | Keep for running/developing; reinstall if deliberately removed |
| `django_backend/.venv/` | Python interpreter environment and packages | Keep for running Django; recreate and reinstall if removed |

Keep `.git/`, environment files, lockfiles, database files, migrations, uploads, backups and source code. An ignored file is not necessarily disposable.

## Next migration steps

1. Verify the migrated projects and content APIs against a disposable PostgreSQL database and the existing Next.js pages.
2. Migrate and verify leads, client workflows, authentication and background jobs. Preserve the existing frontend API contract.
3. Validate a restored database copy, all admin roles, email delivery, media operations and deployment configuration.
4. Deploy Django behind the existing reverse proxy, monitor it, and keep the old backend in a tagged backup until the rollback period ends.

The frontend can use the Django API after every route family has passed compatibility checks. Until then, test incomplete route families against an isolated development server.

## Target structure after migration

```text
banglasketch/
├── frontend/       Next.js website and custom admin
├── backend/        Django API (renamed from django_backend after cutover)
│   ├── banglasketch_api/
│   ├── apps/
│   ├── tests/
│   ├── manage.py
│   └── requirements.txt
```

This is the final layout target. Rename `django_backend` to `backend` only after the API and deployment checks pass; update PM2 paths, scripts, environment loading and documentation together, then recreate its virtual environment at the new path.
